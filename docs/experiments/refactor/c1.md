# C1 canonical data and evaluation qualification — October 7, 2026

**Status:** Implementation, task reviews and final correction checks finished;
completion remains pending final scoped re-review. This report covers the approved
[C1 design](../../superpowers/specs/2026-10-07-c1-canonical-evaluation-design.md),

The [C0 qualification](c0.md) and its artifacts remain historical and unchanged.

Canonical preparation requires explicit source namespace/accession and verified
source-file SHA-256 revisions. Immutable records retain original float32 N/CA/C/O
observations, atom masks, residue correspondence and lineage. Missing observations
stay null; imputed work coordinates never become targets. Export schema 2 joins
admitted rows and declared rejections to the complete canonical population.
Biological identity excludes file placement, display aliases and shard order;
representation and exact replay identities remain separate.

Inventory-union auditing checks every declared split and cluster, including test
members and parent-only records outside loader sources. Canonical case artifacts
(version 1) expand validation members, families and replicates once, with frozen
half-open crops, purpose-separated seeds, group IDs and masks in canonical residue
coordinates. Unavailable representation targets change coverage and denominators;
they do not redraw controls or renumber groups. Missing conditioning, unsupported
crop capacity, unqualified joint exposure and explicit export rejections are
reported separately. Missing/duplicate supposedly admitted rows are integrity errors.
Case counts are distinct from unique proteins. Generation monitoring is capped at
16 expanded cases. Single-process cap rejection precedes device setup; distributed
ranks may initialize existing communication to exchange case/artifact failures,
before any model or output setup.

Native monitoring now selects frozen `case_manifest` families. Old cohort paths,
live case maps, `train.eval.seed`, and `generation.max_samples` are rejected;
`generation.max_cases` defaults to and cannot exceed 16. The one-source unsplit,
unmonitored overfit path remains operational without a scientific evaluation claim.
Full CPU artifact audits precede model construction and run outputs. Case owners
execute singleton crops, exchange errors before reductions and reconcile replicated
uneven tails across workers/ranks. Geometry uses original four-atom availability.

Current-only training checkpoint format 4 contains normalized population/splits,
source representation/replay inputs, resolved cases and evaluation protocol inputs.
The shared reader recomputes saved cross-field bindings without reopening original
artifacts or requiring the saved training device at inference. This verifies saved
metadata consistency; it does not reobserve absent raw inputs or provide authenticity
against coordinated malicious rewriting. Qualified GCP archives retain their separate
contract. Previous STok training formats and exports require regeneration, with no
converter or compatibility layer.

`MDLMRunIdentity.training_signature` hashes the training data projection only.
The external live measurement's `model_identity.training_signature` hashes the
complete native resume signature, including model, seed, optimizer, budget and
execution, together with the current successful-update number. Evaluation-only
overrides preserve both training identities while changing the protocol when
scientific settings change. Actual selected families, representation, decoder and
native source/software/numerical policy determine that protocol. Output/display
aliases and cadences do not. Finite deterministic JSON summaries under
`logs/evaluations/step-{update}-{measurement_sha256}.json` publish atomically;
identical bytes are idempotent and conflicts fail through rank agreement.

Training global occurrence arithmetic, seed purposes, weighted eligible-token
normalization, connected empty supervision, real AdamW decay, successful-update
cadences, CPU scaler skips, clean targets and all-rank logging remain intact.
Canonical IDs replace biological aliases; exact source replay remains a separate
occurrence input. Changed shards/order reject resume despite equal populations.

## Final review correction — startup coordination and empty generation targets

The whole-branch review found two remaining correctness defects: rank-local case
artifact reads could exit before peers initialized communication, and generation
with no effective target cells could be reported as completed. This consolidated
correction also closes the earlier standalone canonical digest minor.

Pure configuration validation remains before device setup. Single-process case
selection and expanded-cap errors still fail there. Launched distributed ranks
retain early case-read/selection/cap errors until existing Accelerator initialization
and immediately exchange them through the existing rank-error boundary. Detection
reuses Accelerate's WORLD_SIZE/MPI/PMI environment information and initialized torch
process groups. Full CPU source/canonical/split audit now has an additional all-rank
agreement before loader/model construction, W&B or run outputs. Invalid distributed
case contracts may therefore initialize communication; this is explicitly permitted
by the approved design, and no new transport is introduced.

Generation cases without effective eligible targets retain their IDs, controls and
unavailable-target counts, receive `unavailable` / `no_targets`, and do not invoke
the sampler. This covers both an originally empty crop within an otherwise admitted
chain and an arm losing all requested target codes. A family without evaluated
cases emits no completion/condition-success metrics even when another family runs;
its count is zero where that dataset's generation metric block is present. Partial
target availability remains usable, and denoising with zero masked cells retains its
existing behavior. Native batch validation now reuses the canonical owner's strict
lowercase hexadecimal SHA-256 predicate.
